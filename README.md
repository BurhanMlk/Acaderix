# Academy Management System

A multi-tenant academy/coaching-center management SaaS built as a Flutter
Android application on Firebase. It provides four role-based experiences:

- **Super Admin** — platform control, academy approvals, subscriptions, broadcasts
- **Academy Admin** — full management of one academy
- **Staff** — role-based teaching/accounts/reception duties
- **Student** — own progress, attendance, fees, results (parents reuse this login)

## Tech stack

| Layer | Technology |
| --- | --- |
| App | Flutter + Dart, Material 3 |
| State | Riverpod |
| Navigation | GoRouter |
| Models | Freezed + json_serializable |
| Backend | Firebase Auth, Firestore, Storage, Messaging, App Check, Crashlytics, Analytics |
| Server | Firebase Cloud Functions (TypeScript) |
| Currency | PKR (via `intl`) |

## Getting started

```sh
flutter pub get
dart run build_runner build
flutter analyze
flutter test
flutter run
```

The app initializes Firebase on startup using
`lib/app/firebase_options.dart`, which was generated by the FlutterFire CLI.

## Firebase setup

1. Create a project in the [Firebase console](https://console.firebase.google.com/).
2. Log in to the Firebase CLI and connect the project:

   ```sh
   firebase login
   dart pub global activate flutterfire_cli
   flutterfire configure --project=<your-firebase-project-id>
   ```

   This regenerates `lib/app/firebase_options.dart` and the platform config
   files (e.g. `android/app/google-services.json`) so the app initializes
   Firebase on startup.

3. Enable the services used by the app:
   - Authentication (Email/Password; later phone where relevant)
   - Cloud Firestore
   - Cloud Storage
   - Cloud Messaging
   - Crashlytics and Google Analytics
   - App Check (Play Integrity for Android)

4. Deploy backend configuration:

   ```sh
   cd functions && npm install && cd ..
   firebase deploy --only firestore:rules,storage:rules,functions
   ```

> ⚠️ Never commit `lib/app/firebase_options.dart` (or any service-account key)
> for a private project. `Firebase Admin SDK` credentials are used **only**
> inside Cloud Functions.

## Android release signing

Release builds require a private upload keystore and `android/key.properties`.
Both are ignored by Git. Use your existing upload keystore if this app has
already been published; generating a new one will not replace the original
signing key.

Create `android/key.properties` locally with the values for your keystore:

```properties
storePassword=<keystore password>
keyPassword=<key password>
keyAlias=<key alias>
storeFile=../<keystore filename>
```

`storeFile` is resolved relative to `android/app`. Keep the keystore and
passwords private, and do not commit them. Then build a signed release:

```sh
flutter build appbundle --release
```

Debug builds do not need release signing credentials. Without this file or
the referenced keystore, a release build intentionally fails rather than
signing with a debug key.

## Local emulator

```sh
firebase emulators:start
```

Run the app against the emulator by pointing the Firebase options at
`10.0.2.2` (Android emulator) with `useEmulator: true` during development.

## Firestore rules

`firestore.rules` and `storage.rules` currently ship **secure by default**
(all access denied). Granular role- and tenant-scoped rules are added in
Phase 10. Privileged operations always go through Cloud Functions, which
implement their own authorization because the Admin SDK bypasses rules.

## Security notes

- Roles come from Firebase custom claims, never from the client.
- Student temporary PINs are never stored in plaintext and expire quickly.
- Financial records (invoices, payments, adjustments, refunds) are immutable
  and posted idempotently by trusted code.
- Tenant isolation is enforced by rules + claims + server-side checks, not by
  hiding screens.
